# Deploy Refund Relay on Render

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/lewisjohnvillamor/paypal_hackaton)

`render.yaml` in the repo root is a Render Blueprint: one Node web service on the **Starter**
plan with a 2 GB persistent disk at `/var/data` for the SQLite database and the evidence photos,
a `/healthz` health check, and every setting the hosted judge demo needs. It runs on the PayPal
**sandbox** only; the app refuses to start against live PayPal.

## Cost and plan

| Plan | Price | Fits the demo? |
| --- | --- | --- |
| Free | $0 | No. It spins down after 15 minutes idle (about a minute of cold start for the next judge) and cannot have a disk, so every restart wipes orders, claims and photos. |
| **Starter** (what `render.yaml` uses) | $7 a month + $0.25 per GB of disk (2 GB = $0.50) | Yes. Always on, no cold starts, data survives deploys. |

Render bills by the second, so keeping it up from now until judging ends (mid-December) costs
roughly $15 in total.

## Steps

1. **Open the Blueprint.** Click the button above (or Render dashboard > **New** > **Blueprint**,
   pick `lewisjohnvillamor/paypal_hackaton`, branch `main`). Render reads `render.yaml` and shows
   one service, `refund-relay`, and one disk.
2. **Fill in the secrets it asks for.** Everything else is already set in `render.yaml`.

   | Variable | Value |
   | --- | --- |
   | `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` | Sandbox REST app (developer.paypal.com > Apps & Credentials > Sandbox) |
   | `PAYPAL_MERCHANT_ID` | Optional: the sandbox Business account's payer ID. Leave blank to skip the payee check. |
   | `TYPESAFE_API_KEY` | Jev API key |
   | `ANTHROPIC_API_KEY` | Needed for the refund agent's plain-English rules and remedy suggestions |
   | `ANTHROPIC_WORKSPACE_ID` | Only if the key is not scoped to a workspace |
   | `MERCHANT_PASSWORD` | Any password of 12+ characters. With `PUBLIC_DEMO=1` it is **printed on the merchant sign-in page**, so do not reuse a real one. |
   | `DEMO_BUYER_EMAIL`, `DEMO_BUYER_PASSWORD` | The sandbox **Personal** (buyer) account, shown to judges under the PayPal button |

   `SESSION_SECRET` and `CREDENTIALS_KEY` are generated by Render. Do not change them later:
   that signs everyone out and makes connected stores reconnect PayPal.
3. **Apply.** The first build takes 2 to 4 minutes (`npm ci --omit=dev`, then `npm start`).
4. **Check it.** Open `https://<service>.onrender.com/healthz`; it should return `{"ok":true,...}`.
   Then run the three-minute tour from the README on the hosted URL: buy the white mug, report it
   with `demo-photos/1-kit-chipped-mug.jpg`, and watch the agent refund it.
5. **Put the URL on Devpost** (the demo link field) and in the README's "Try it" section.

## Settings `render.yaml` already makes

| Variable | Value | Why |
| --- | --- | --- |
| `PUBLIC_DEMO` | `1` | Prints the merchant password and sandbox buyer sign-in on the pages, and turns on the agent's starter rule |
| `REPEAT_CLAIM_LIMIT` | `0` | Every judge pays as the same sandbox buyer; without this each claim after the first is flagged as a repeat claimant and the agent keeps its hands off |
| `APP_BASE_URL` | not set | The app uses Render's own `RENDER_EXTERNAL_URL` (`https://<service>.onrender.com`). Set it only if you add a custom domain. |
| `TRUST_PROXY` | `1` | Rate limits per buyer instead of per Render load balancer |
| `DATABASE_PATH`, `UPLOAD_DIR` | on `/var/data` | Survive deploys and restarts |
| `BACKUP_INTERVAL_HOURS` | `24` | Daily database copy in `/var/data/backups` (keeps 7), on top of Render's disk snapshots |
| `NODE_VERSION` | `22.22.0` | The app uses Node's built-in SQLite (Node 22.15 or newer) |

## Notes

- A persistent disk pins the service to one instance and turns off zero-downtime deploys; each
  deploy has a few seconds of downtime while the old instance stops. Avoid deploying while
  judges are likely to be on it.
- Auto-deploy is on for `main`, so merging a PR redeploys the demo.
- Logs: one JSON line per API request with an `X-Request-Id` (Render dashboard > Logs).
- To reset the demo data, open the Render **Shell** and run
  `rm /var/data/refund-relay.db* && rm -rf /var/data/uploads`, then **Manual Deploy > Restart**.
